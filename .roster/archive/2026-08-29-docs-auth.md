# Update docs/nextjs-research.md with correct Next.js 16 auth best practices

## Spec

The goal is to make `docs/nextjs-research.md` an accurate, comprehensive guide for implementing authentication and authorization in a Next.js 16 App Router project (with React 19, Tailwind v4, Turbopack), based on current Next.js 16 and Auth.js v5 documentation and the project context in `README.md`/`package.json`.

What must change:
- Research current Next.js 16 App Router authentication/authorization conventions (middleware/proxy, route protection, Server Actions, Route Handlers, environment/security).
- Research current Auth.js v5 (`next-auth@beta`) configuration for App Router (providers, credentials, session/JWT, type augmentation, custom pages, `auth()` helper).
- Compare findings to the existing `docs/nextjs-research.md` (especially sections 2–5 and section 7 sources) and identify outdated, incorrect, or missing content with `file:line` references.
- Update `docs/nextjs-research.md` to fix errors and fill gaps, preserving the Russian language and the document structure where accurate.
- Add or correct code examples to match Next.js 16 and Auth.js v5 APIs.
- Update source links (section 7) to point to the current documentation pages.

What must not change:
- The overall role of the document as a research/onboarding guide.
- Accurate sections not related to auth (e.g., project initialization, Tailwind v4 basics).
- The `package.json`, `README.md`, source code, or agent-roster files unless the researcher finds a clear, documented reason, which must be reported.
- Do not introduce secrets or credentials.

Verification:
- `docs/nextjs-research.md` renders as valid Markdown and is internally consistent.
- `npm run lint` passes after dependencies are installed.
- `npm run build` passes after dependencies are installed.
- The code examples in the doc match the installed `next@16.3.3`, `react@19.2.8`, `eslint-config-next@16.3.3`, and the latest Auth.js v5 guidance at the time of research.

### Research summary (pre-cycle)

Researcher confirmed `proxy.ts` is the Next.js 16 replacement for `middleware.ts` and the App Router `auth()` / Route Handler wrapping pattern is correct. The main fixes required in `docs/nextjs-research.md`:

1. Use canonical Auth.js v5 path `auth.ts` (or `src/auth.ts`), not `src/lib/auth.ts`.
2. Let `Google()` provider infer `AUTH_GOOGLE_ID`/`AUTH_GOOGLE_SECRET`; do not pass `clientId`/`clientSecret`.
3. Explain `SessionProvider` must live in a client wrapper (`app/providers.tsx`) because the App Router root layout is a Server Component.
4. Replace `callbackUrl` with `redirectTo` in client-side `signIn`.
5. Replace `isRedirectError` from `next/navigation` with `unstable_rethrow`; call it first in the catch block.
6. Update `next-auth.d.ts` type augmentation to extend `DefaultSession["user"]` and use `next-auth/jwt` JWT types, preserving default fields.
7. Update `proxy.ts` matcher to also exclude `favicon.ico`, `sitemap.xml`, `robots.txt`.
8. Add a new section covering Next.js 16 authorization APIs: `experimental.authInterrupts`, `unauthorized()`, `forbidden()`, `unauthorized.tsx`/`forbidden.tsx`.
9. Add missing canonical source URLs in section 7.
10. Note the repo currently has no `next-auth` dependency, so the install step (`npm install next-auth@beta` + `npx auth secret`) remains required for actual implementation.
